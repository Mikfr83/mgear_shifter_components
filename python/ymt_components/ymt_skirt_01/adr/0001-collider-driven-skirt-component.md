# ADR-0001: Collider-Driven Skirt Component Built on skirtBellCollider

Status: Proposed
Date: 2026-08-27
Owner: ymtshiftercomponents maintainers
Supersedes: none
Superseded by: none

Design review: adversarial reviews by Codex and GLM, adjudicated through a Grok
counter-review (2026-08-27, reports under `docs/reference/skirt_design_review/`).
All formula-level pins below were verified against
`docs/reference/colliders/skirtBellCollider.cpp` (`initialize`, `compute`,
`postConstructor`, `getAxis`, `createRingMatrix`).

## Context

Skirt rigs need bind joints that follow the legs without interpenetration. The
`colliders` Maya plugin (azagoruyko/colliders, bundled in this repository under
`platforms/win64_<version>/plug-ins/colliders.mll`; reference sources copied to
`docs/reference/colliders/`) provides a `skirtBellCollider` node: it consumes
world matrices for a bell transform and left/right hip, knee, heel, and outputs
a deformed NURBS cone (`outputSurface`) that resolves leg-versus-skirt
collision procedurally.

Node semantics that constrain this design (verified in `compute`):

- The skirt direction is `getAxis(bellMatrix, bellAxis)`: one of the six signed
  local axes of the bell input matrix. The surface twist comes from the bell
  matrix X axis. The node never derives the axis from the leg positions.
- Vertical placement uses per-leg chain distances, not straight-line distance:
  `L_thigh`/`L_calf` are the averaged left/right bone lengths,
  `d_hip = |hipMid - bell|`, `d_knee = d_hip + L_thigh`,
  `d_heel = d_knee + L_calf`. The hem sits at
  `h_val = d_hip + (d_knee - d_hip) * height` (Short) or
  `h_val = d_knee + (d_heel - d_knee) * height` (Long).
- The surface has only 3 (Short) / 4 (Long) V level rings; V is degree 1 with
  world-distance knots; U is periodic. `bellScaleRamp` is sampled only at the
  level-ring stations normalized by `h_val` (Short stations are scaled by
  `h_val / d_knee`). Exact per-row profile reproduction is therefore not a node
  capability.
- `ringScale`/`bellScale` Y components multiply lengths already derived from
  world matrices; X/Z multiply normalized axes.
- `tightness` only affects the Long-type hem ring; `collision`/`falloff` affect
  every solver pass.
- `createRingMatrix` re-aims the selected ring axis at its target, so the
  `leftRingAxis`/`rightRingAxis` enums effectively choose the ring twist basis.
- Output surface CVs are produced in world space.

Requirements fixed by the rigger:

- Guide places a rows x cols grid of locators defining the bind joints. Rows
  run vertically (waist to hem), columns run around the circumference,
  generated front-start clockwise, freely movable afterwards.
- Waist and leg (hip/knee/heel, both sides) references are guide locators in
  this component; connecting them to other components' rig nodes is deferred.
- An FK control sits between each surface-driven npo and its bind joint.
- The cone axis is the direction from the waist reference toward the midpoint
  of the two heel references.
- `skirtType` is not exposed as a guide parameter.
- `bellScaleRamp` is fitted dynamically from the authored grid rows.
- Animator attributes: `collision`, `tightness`, `falloff`.
- Maya 2022 (Python 3) and later; plugin binaries per Maya version are deployed
  into `platforms/`.
- Component root world scale is wired into the fitted bell/ring scale values.
- No guide symmetrization support.

Prior art: `ymt_feather_ribbon_01` establishes the variable-count guide locator
pattern (string parameters plus a settings-UI rebuild button, dynamic
collection in `setFromHierarchy`).

## Decision

Add `python/ymt_components/ymt_skirt_01/` as a self-contained component that
creates and configures one `skirtBellCollider` node per component instance.
The component re-implements the small node-creation portion itself; it does
not import `colliders/scripts/colliders.py` at runtime, and it must not copy
that script's silent fallbacks (zero-length axis defaulting, hip-distance
substitution). The only runtime dependency is the plugin, loaded in
`addObjects` via `cmds.loadPlugin("colliders")` with a clear error when
unavailable (pattern: `_ensure_rotation_driver_plugin` in
`ymt_feather_ribbon_01`).

### Guide contract

- `root` plus fixed reference locators: `waist`, `hip_L`, `knee_L`, `heel_L`,
  `hip_R`, `knee_R`, `heel_R`.
- Grid locators `skirt_{row}_{col}_loc`, generated by a settings-UI button from
  `rows`/`cols` integer parameters, serialized and re-collected dynamically
  following the `ymt_feather_ribbon_01` pattern. Row 0 is the waist-most row.
  A display curve per row visualizes the loops.
- Generation defaults (regeneration deletes existing `skirt_*_loc` first):
  rows placed along the cone axis at equal spacing covering axial fractions
  0.15 to 0.90 of `|heelMid - waist|`; per-row circle radius interpolated
  linearly from `|hip_L - hip_R| / 2` (row 0) to 1.6x that (hem row); column 0
  at the character front (guide root local +Z projected onto the plane
  perpendicular to the axis), column index increasing clockwise when viewed
  from the waist looking down the axis toward the hem.
- Guide parameters: `rows` (long, min 2), `cols` (long, min 3), `ctlSize`
  (double), `addJoints` (bool), `collision` (double, 0..1, default 1.0),
  `tightness` (double, 0..1, default 0.5), `falloff` (double, -1..1,
  default 0.0), and the leg ring size: `ringScaleX`/`ringScaleZ` (double,
  min 0.001, default 1.0, multipliers over the hip half-distance) and
  `ringScaleY` (double, min 0.001, default 1.0, the node's ring height
  coefficient, passed through). Ranges mirror the node attribute ranges from
  `initialize`. The settings window gives visual feedback for the ring size:
  changing a ringScale spin box redraws template ellipse curves at the hip,
  knee, and heel of each leg (radii = multiplier x hip half-distance,
  perpendicular to the leg axis); the preview curves are deleted when the
  window closes and are never serialized into the guide.

### Build-time validation (raise `RuntimeError`, no fallbacks)

| Condition | Action |
|---|---|
| Plugin `colliders` cannot be loaded | raise with plugin name and Maya version |
| Any fixed reference transform missing or non-finite | raise, name the reference |
| Collected grid names != exact set {skirt_r_c_loc: 0<=r<rows, 0<=c<cols} | raise, list missing/extra/duplicate names |
| rows < 2 or cols < 3 | raise |
| `\|heelMid - waist\|` < 1e-3 x guide size | raise (degenerate axis) |
| Front vector parallel to cone axis within 1e-3 | raise (twist undefined) |
| Row centroid axial projections not strictly increasing with row index | raise |
| Any row mean radius < 1e-3 x guide size, or two same-row locators coincident within that epsilon | raise |
| Hip-to-hip distance < 1e-3 x guide size | raise |
| Fitted `height` outside [0.01, 1.0] | raise (never clamp) |
| Interpolation denominators (`d_knee - d_hip`, `d_heel - d_knee`) < 1e-5 | raise |
| Aim construction up-vector parallel to aim direction within 1e-3 | raise |

### Cone fit (all quantities from guide rest positions, world space)

- `W` = waist, `heelMid` = midpoint of heels, axis `a = normalize(heelMid - W)`.
- Bell frame `B` (fed to `bellMatrix` through the internal waist reference):
  orthonormal, translation `W`, local +Y = `a`, local +X = normalize(front
  projected perpendicular to `a`) where front = guide root local +Z in world
  space; local +Z completes the right-handed frame. `bellAxis` = Y (enum 1) by
  construction. Dominant-axis inference (`_findAxis`) is not used for the bell.
- Chain distances exactly as the node computes them: `L_thigh`, `L_calf` from
  averaged left/right bone lengths, `hipMid` = hip midpoint,
  `d_hip = |hipMid - W|`, `d_knee = d_hip + L_thigh`,
  `d_heel = d_knee + L_calf`.
- Hem statistic: `A_r` = (row r centroid - `W`) dot `a`; the hem row is the
  last row; `A_hem = A_(rows-1)`.
- `skirtType` derived, sharing the same statistic as the height fit: Long when
  `A_hem > d_knee`, Short otherwise. Height inversion:
  Short `height = (A_hem - d_hip) / (d_knee - d_hip)`;
  Long `height = (A_hem - d_knee) / (d_heel - d_knee)`.
  Out-of-range results raise (see table). With these values the node's `h_val`
  equals `A_hem`.
- `bellScale` = (`R_hem`, 1.0, `R_hem`) where `R_hem` = mean perpendicular
  distance of hem-row locators from the axis line through `W`.
- `ringScale` = (`|hip_L - hip_R| / 2 * ringScaleX`, `ringScaleY`,
  `|hip_L - hip_R| / 2 * ringScaleZ`) from the guide parameters.
- `bellScaleRamp`: remove the `postConstructor` default entries, then write one
  entry per row: position `A_r / A_hem`, value `R_r / R_hem` (`R_r` = row mean
  perpendicular radius), interpolation linear (`kLinear`). This fit is
  explicitly approximate: the node samples the ramp only at its 3/4 level
  stations, so authored radii between stations are reproduced only where
  stations land; non-monotonic profiles are permitted but smeared by the
  degree-1 V surface. The fit targets the undeformed cone; any automated
  verification must evaluate with `collision` = 0.
- Ring axes: internal hip and knee reference transforms are aim-constructed
  (local +X toward their child target: hip->knee, knee->heel; up-vector = bell
  frame local +X), heel references inherit the knee frame orientation with
  their own translation. `leftRingAxis` = `rightRingAxis` = X (enum 0) by
  construction. No dominant-axis inference, no tie-breaking needed.

### Internal reference transforms (interim interface)

- Names: `getName("waistRef")`, `getName("hipRef_L")`, `getName("kneeRef_L")`,
  `getName("heelRef_L")` and `_R` equivalents; parented under the component
  root so their `worldMatrix` inputs scale with the rig; hidden via a shared
  refs group, translate/rotate unlocked and non-keyable so riggers can
  constrain them manually or from a custom step.
- The component exposes `get_skirt_collider_refs()` returning
  `{"waist": node, "hip_L": node, ...}` as the stable hook for a future
  connector ADR.
- v1 is therefore a static-cone collision preview plus manual FK rig unless
  the references are externally constrained; the collider reacts to whatever
  drives those references.

### Surface, drivers, controls, joints

- `outputSurface` -> `rebuildSurface` (direction = V, spansU = 1, spansV = 4,
  cubic degree, keepRange = 0 so V renormalizes to [0, 1]) -> NURBS shape under
  a transform named `getName("colliderSurface")` kept at identity world
  transform with `inheritsTransform` off and hidden. World-space CVs plus a
  non-identity container would double-transform; identity is part of the
  contract.
- UV mapping is parametric per row/column index, not closest-point. Row r maps
  to `v_r = minV + (A_r / A_hem) * (maxV - minV)` (actual min/max read from the
  rebuilt shape). Column U values are calibrated by angle, because the node's
  knot origin and sweep direction are not guaranteed to align with the bell
  front axis: the build samples the rest surface densely around U at mid V,
  measures each sample's angle about the cone axis (zero at the bell front
  axis, positive clockwise viewed from the waist toward the hem), and assigns
  each column the sampled U whose angle is closest to the column's circular
  mean authored angle. This is a deterministic measurement, not a fallback.
- Driver chain per cell (as the reference tool):
  `pointOnSurfaceInfo` (`worldSpace[0]`, position + normal + tangentU/V into a
  `fourByFourMatrix` world frame) -> `multMatrix` [rest-offset, fourByFour
  output, npo `parentInverseMatrix`] -> `decomposeMatrix` -> npo translate and
  rotate. No scale channels are driven.
- Rest offset, stated in Maya's row-vector convention (multMatrix multiplies
  its inputs in index order, `matrixSum = in0 * in1 * in2`):
  `O = M0 * inverse(D0)` computed once at build, where `D0` is the cell's rest
  driver world matrix and `M0` is the radial rest frame: Y = the surface
  normal normalized and sign-corrected to point radially outward from the cone
  axis, Z = tangentV projected orthogonal to Y, normalized, and sign-corrected
  to point toward the hem, X = Y cross Z (the circumference tangent),
  translation = the authored locator world position. At rest `O * D0 = M0`, so
  every npo sits at its authored position with X along the circumference,
  Y outward, and Z down the skirt (a front-center cell reads approximately
  (cone-slope, 0, 0) in XYZ euler, not identity).
- Layering per cell: npo -> FK control -> bind joint. Joints are flat: every
  enabled cell appends its own `[fk_ctl, "{row}_{col}", "parent_relative_jnt"]`
  entry to `jnt_pos`, ordered row-major. `addJoints` = False builds controls
  but appends nothing. Columns are never chained.

### Animator attributes and scale

- `addAttributes` exposes `collision` (0..1), `tightness` (0..1), `falloff`
  (-1..1) on the ui host, seeded from the guide parameters and connected to
  the node. Consequence note for animators: `tightness` has no effect on
  Short-type skirts.
- Global scale: fitted radii are stored in component-root local units
  (world measurements divided by the root world scale at build). At build a
  `decomposeMatrix` on the root `worldMatrix` feeds multiply nodes:
  `bellScale.x = fitX * scale.x`, `bellScale.z = fitZ * scale.z`, same for
  `ringScale` X/Z. Y components are not wired to root scale: `bellScale` Y
  stays 1.0 and `ringScale` Y holds the static `ringScaleY` setting (both
  multiply already-world-derived lengths inside the node). `height` is not
  wired (dimensionless over
  matrix-derived distances that scale automatically). Scale is applied exactly
  once. Supported invariant: uniform positive rig scale; non-uniform scale,
  reflection, and shear are out of contract.

## Considered Options

1. Reference legs/waist by relative-name string parameters resolved at connect
   time
   - Pros: rig-time connection to animated leg joints works out of the box.
   - Cons: couples the component to specific leg component types; more scope.
2. Reference legs/waist with guide locators, defer rig connection (chosen)
   - Pros: self-contained guide; the fit needs only rest positions.
   - Cons: static inputs until a follow-up wires them; requires the interim
     interface pinned above.
3. Import `colliders/scripts/colliders.py` at build time
   - Pros: reuses the reference implementation.
   - Cons: external checkout path dependency, UI-oriented code, silent
     fallbacks that violate repository rules. Rejected.
4. Drive joints directly from surface transforms (no FK layer)
   - Pros: fewer nodes.
   - Cons: no manual adjustment path. Rejected by requirement.
5. Expose `skirtType` as a guide parameter
   - Pros: explicit control.
   - Cons: derivable from the grid via the shared hem statistic; one less
     setting to drift. Rejected.
6. Closest-point UV mapping of grid locators onto the rest surface
   - Pros: attaches each cell to its geometrically nearest sheet.
   - Cons: periodic-U seam makes it two-valued at the front seam, indentations
     create near-ties between sheets, and regeneration can reorder columns; it
     would need an injectivity/monotonicity gate to be safe. Parametric
     row/col mapping (chosen) is deterministic, matches the reference tool's
     uniform sampling, and the rest offset preserves authored placement.
7. Exact per-row ramp reproduction
   - Pros: authored profile matched everywhere.
   - Cons: not representable; the node samples the ramp at 3/4 stations over a
     degree-1 V surface. Chosen: explicitly approximate fit with pinned
     normalization.
8. Dominant-axis inference for bell and ring axis enums (reference tool
   behavior)
   - Pros: works for axis-aligned guides.
   - Cons: cannot realize arbitrary waist-to-heel directions (up to ~55 degree
     error), tie cases are order-dependent, mirrored guides can defeat the
     node's L/R defaults. Chosen instead: aim-constructed frames with enums
     fixed by construction.

## Consequences

The component builds a procedural collision skirt from guide data alone and
can be dropped into any biped guide. Out of the box the collider inputs are
static: the rig is a collision preview plus manual FK skirt until the internal
references are constrained to the rig (manually, via custom step, or a future
connector ADR). The dynamic ramp fit ties the collider profile to the authored
grid within the node's 3/4-station representation; re-fitting happens on every
build. All geometric preconditions raise instead of falling back, so malformed
guides fail loudly at build time. The component depends on `colliders.mll`
for the running Maya version (module wiring in `ymtshiftercomponents.mod`
covers win64 2019-2030 directories; binaries are maintained for 2022+).
Runtime validation of collider behavior requires Maya; static checks cannot
cover it. Non-uniform rig scale is explicitly unsupported.

## Confidence and Revisit Trigger

Confidence: Medium

Revisit this ADR when:

- the leg/waist references need to follow the animated rig (connector or
  custom-step contract in a companion ADR consuming
  `get_skirt_collider_refs()`).
- production assets show the parametric UV mapping or the station-limited ramp
  fit deviating from authored grids beyond acceptable tolerance (define a
  measured fit-error threshold at that point).
- non-uniform rig scale becomes a requirement.
- the plugin adds denser V sampling or ramp evaluation, making a closer-to-
  exact profile fit representable.
